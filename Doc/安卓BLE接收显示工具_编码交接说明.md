# 安卓 BLE 接收显示工具：项目与编码交接说明

更新日期：2026-10-31。核对范围：第二版图表/报警需求、当前源码及 JVM 验证；第一版 BLE 收发已由用户确认，新增界面尚未完成实机验收。

## 1. 项目背景与当前目标

项目最终用于纸尿裤内液体检测：初级芯片 MTCH9010 检测液体后，启动 FDC1004 测量，由 STM32L010C6T6 控制，并通过 E104-BT5010A BLE 模块向安卓手机传输信息。

上述为项目背景，不能直接作为当前测试固件行为的描述。当前接口规范对应 `L010C6T6_FDC_BLE.test` 测试固件：上电后 BLE 保持唤醒，FDC1004 执行约 20 秒校准，随后轮询四通道，每约 2 秒输出一组四行测量文本。

当前已实现 BLE 接收、调试文本、四通道实时曲线和基础电容阈值报警；尚未实现漏尿判断。

## 2. 已确认范围

- App 在监测页展示最近 60 秒的 CH1～CH4 曲线，四个通道分别占据独立横轴轨道并共用自动缩放纵轴。
- 监测页提供「报警设置」折叠栏，当前唯一默认规则为任一通道严格大于 1.0 pF 时报警；阈值不可编辑。
- 调试页保留原始文本、扫描按钮和设备列表；底部导航用于切换监测/调试。
- 报警弹窗标明超限通道和当前值，可关闭；关闭后保持静默，四个通道都收到合法低值后重新布防。
- 断开时保留当前会话数据，再次连接成功并完成通知订阅后清空图表、报警状态和调试文本。
- 只考虑 App 在前台运行；不要求后台接收或屏幕常亮。
- 同时只连接一个硬件设备。
- 扫描后列出匹配设备，由用户点击目标设备连接。
- 自动完成服务发现和通知订阅，然后持续接收显示文本。
- 断开后由用户重新扫描、点击连接，本阶段不做自动重连。
- 调试页提供连接所需操作、连接状态和可滚动接收区域。

### 本阶段排除项

不实现漏尿判断、其他报警规则、阈值编辑、报警声音、振动、报警历史、数据持久化、图表缩放/导出、患者管理、后台运行或下行业务命令。

## 3. 连接与操作流程

1. 启动 App，显示“未连接”。检查 BLE 支持、蓝牙开启状态和所需权限；条件不满足时给出明确提示。
2. 用户在调试页点击“扫描设备”，列出匹配设备，优先按服务 FFF0 筛选，设备名作为辅助识别。名称可能修改，不能只依赖名称，也不能把同型号名称视为唯一身份。
3. 用户点击目标设备，停止扫描，显示“连接中”，建立 GATT 连接。
4. 连接成功后发现服务，查找 FFF0 下的 FFF1；缺失时显示明确错误。
5. 开启 FFF1 notification，并完成 CCCD 通知订阅配置。**订阅成功后才显示“已连接，等待数据”。**
6. 收到数据后，拼接完整文本行并显示。不发送“开始采集”命令，不依赖启动横幅或 CAL done 才开始接收。
7. 断开后显示“连接已断开”，保留当前图表、报警状态和完整文本，清除未完成行缓存；再次连接成功并完成通知订阅后清空旧会话数据。

不以用户先到系统蓝牙设置页面配对为前提。若实际设备要求配对或认证，应根据实机结果补充，不得假定已经验证。

## 4. BLE 接口基线

| 项目 | 定义 |
|---|---|
| 模块 | E104-BT5010A，BLE 5.0 |
| 角色 | 硬件为 Peripheral / 从机，手机作为主机连接 |
| 广播 | 普通广播，可连接；不是 iBeacon 模式 |
| 默认设备名 | E104-BT5010A，可能被修改 |
| 服务 | `0000fff0-0000-1000-8000-00805f9b34fb` |
| 接收特征 | `0000fff1-0000-1000-8000-00805f9b34fb`，Read / Notify |
| 下行特征 | FFF2，当前固件不处理下行业务命令，不使用 |
| 配置特征 | FFF3，仅模块空中配置，本阶段不使用 |
| 编码与分行 | ASCII 文本，CRLF（0x0D 0x0A）结束 |

以上来自硬件方规范，实际固件及配置仍需联调核实。模块 UART 参数为 115200、8N1、无流控，这是硬件侧配置，手机不需要配置串口。

### 数据处理要求

- 通知边界不等于文本行边界：一行可跨多个通知，一个通知也可含多行。
- 先缓存原始字节，再按 CRLF 提取完整行；兼容默认 MTU 的分片，不以大 MTU 协商成功为接收前提。
- 调试页原样显示测量、校准、错误及未知文本；监测页仅解析 `CH1: <数值> pF` 形式的有效行。
- 无效通道值、校准和错误文本不进入图表、不触发报警，也不作为报警恢复的低值。
- 断线清除未完成行，避免与下一连接的数据拼接。
- 为接收缓存和显示记录设置上限，异常字节、未知行、超长无换行数据不得导致崩溃或内存无限增长。
- 不要求补回连接前或断线期间的数据；当前固件没有补发、业务确认或事件编号机制。

典型测量文本（每行以 CRLF 结束）：

```text
CH1: 0.012 pF (dC, raw=6291, capdac=1)
CH2: -0.018 pF (dC, raw=-9437, capdac=1)
CH3: 0.003 pF (dC, raw=1573, capdac=1)
CH4: 0.021 pF (dC, raw=11010, capdac=1)
```

也可能收到 `CAL: start, 20 s zeroing`、`CAL done`、`CH2: INVALID`、错误消息等，均作为文本显示。SAT、ERROR 不代表已确认漏尿，不触发声音或振动。

## 5. 界面与状态

- 调试页扫描操作和设备列表：显示可辨识的设备信息，支持点击连接。
- 状态区域：未连接、扫描中、连接中、发现服务中、订阅中、已连接等待数据、接收中、连接已断开，以及具体失败原因。
- 监测页：报警设置折叠栏、四通道 60 秒曲线及独立横轴。
- 调试页：可滚动原始文本；采用有上限的记录保留策略。
- 断开后当前 App 会话中的数据保留；新连接完成通知订阅后清空。
- 任一通道超过默认阈值时在两栏均弹出报警；关闭后不重复弹窗，四通道均恢复低值后重新布防。

界面文案使用中文。扫描无结果、权限拒绝、蓝牙关闭、连接失败、服务缺失、订阅失败应提供可理解的提示，不将失败显示为已连接。

## 6. 编码与交付要求

当前工程为 Kotlin + Jetpack Compose，minSdk 31、targetSdk 36。BLE 连接、文本分行、电容解析/报警和界面已分层；依赖与插件版本由 `gradle/libs.versions.toml` 管理。

交付可构建的项目源码、简明构建与安装说明；环境允许时提供调试安装包。明确报告构建、自动化验证、真机安装、硬件联调各自是否完成，不把模拟测试当作实机通过。

## 7. 验收标准

1. 安卓真机可以扫描到目标模块，由用户点击建立连接。
2. 服务发现及 FFF1 通知订阅成功后，状态正确更新。
3. 调试页持续显示与硬件发送一致的完整文本行。
4. 对通知任意拆分或多行合并，仍能正确恢复文本行；包含跨通知拆分的 CRLF。
5. 中途连接、未收到启动横幅或 CAL done 时仍能显示后续数据。
6. 断开后保留当前数据，不拼接旧半行；重新连接成功并完成通知订阅后清空旧会话，再继续接收。
7. 异常字节、未知文本、超长无换行输入及长时间接收不会导致崩溃或无限占用内存。
8. 电容解析、任一通道超限报警、关闭后静默及四通道恢复后重新布防符合已确认规则；不实现声音、振动或业务命令发送。
9. 监测页显示最近 60 秒的四通道曲线，各通道横轴独立、时间范围同步，纵轴按窗口内数据自动缩放。
10. 断开时数据保留；重新连接成功并完成订阅后图表、报警状态和调试文本全部清空。

分行、解析、报警和窗口裁剪已由 JVM 测试验证；新图表与报警界面、连接和真实数据接收仍须用目标硬件实机验收。
